# SigmaStudio Exports

This document describes the files generated by SigmaStudio and the conventions required
when using them through the SigmaStudioFW interface.

## Program data

`adau_1787_IC_1_SIGMA.h` stores the SigmaDSP program in the following buffer:

```c
ADI_REG_TYPE Program_Data_IC_1_Sigma[PROGRAM_SIZE_IC_1_Sigma] = {...}
```

Each program word occupies 5 bytes. The words are stored consecutively in a flat buffer
whose total size is `<number_of_words> * 5`. The generated header also defines this size:

```c
#define PROGRAM_SIZE_IC_1_Sigma 4310
```

The address of the first program-memory word is defined separately:

```c
#define PROGRAM_ADDR_IC_1_Sigma 20480
```

Because the ADAU1787 supports burst writes, the host needs to provide only the address of
the first word. The DSP automatically increments its internal address for each subsequent
word.

The complete program is written to memory once, as a single burst, during startup.

## Parameter data

`adau_1787_IC_1_SIGMA.h` stores the SigmaDSP parameters in a similar buffer:

```c
ADI_REG_TYPE Param_Data_IC_1_Sigma[PARAM_SIZE_IC_1_Sigma] = {...}
```

Its size is defined by:

```c
#define PARAM_SIZE_IC_1_Sigma 2372
```

### Parameter-memory base address

SigmaStudio exports the address of the first parameter word as `0`. This is the address
the DSP uses internally. External interfaces such as I2C, however, access parameter memory
through a window that begins at `0x2000`.

After each export, manually change the following definition to `0x2000` so that parameters
are written to the correct address:

```c
#define PARAM_ADDR_IC_1_Sigma 0x2000
```

A build-time assertion reports an error if the address has not been updated:

```c
BUILD_ASSERT(PARAM_ADDR_IC_1_Sigma == ADAU1787_PARAM_RAM_BASE, "Param Memory Address must be set to 0x2000.");
```

### Parameter addresses and values

`adau_1787_IC_1_SIGMA_PARAM.h` defines the address and value of each processing-block
parameter. A parameter is typically represented by macros whose names end in `_ADDR`,
`_FIXPT`, `_VALUE`, and `_TYPE`.

The `_ADDR` macros already include the `0x2000` offset and can be used directly when
writing individual parameter words.

The `_FIXPT` macros represent the 32-bit Q5.23 fixed-point type used by the DSP. They require additional handling before their values can be written:

- serialize the 32-bit value into a big-endian byte array;
- for negative values, clear the upper nibble before transmission.

The second step is necessary because SigmaStudio sign-extends the exported 28-bit value to
32 bits. As a result, a negative `_FIXPT` value has its upper bits set. The ADAU1787
external-interface format instead requires the 28-bit parameter word to be zero-padded to
32 bits.

For example, the startup buffer in `Param_Data_IC_1_Sigma` encodes a negative value as:

```c
{0x0F, 0x87, 0xE5, 0x5F}
```

The corresponding `_FIXPT` macro in `adau_1787_IC_1_SIGMA_PARAM.h` is:

```c
0xFF87E55F
```

This difference is expected. The startup buffer contains the bytes that are written to the
DSP, whereas the `_FIXPT` macros primarily serve as developer references and must be
converted before use in an external write.

## Register values

As with the program and parameter data, `adau_1787_IC_1_SIGMA.h` contains the register
values written during startup. The corresponding register addresses come from
`adau_1787_IC_1_SIGMA_REG.h`.

The register values defined in `adau_1787_IC_1_SIGMA_REG.h` are not used for the initial
write; they serve as references. Its address macros are ready to use without adjustment,
and the file also provides shift and mask macros for manipulating individual fields.
